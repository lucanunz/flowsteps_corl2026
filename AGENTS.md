# AGENTS.md

Guidance for coding agents working in this repository. Read this before editing
anything under `scripts/` or `data/`.

## What this repository is

A frozen, self-contained export of the paired evaluation logs behind the paper:
193 setting files, 444,329 normalized episodes, seven policies, five benchmark
suites. It is an **analysis and reproduction** repository — no simulators, no
GPUs, no model weights, no original log tree required. Everything the figures
need is committed as JSON.

The data is treated as read-only evidence. Agents should change analysis code
and documentation, not the contents of `data/`.

## Setup

```bash
python -m pip install -r requirements.txt          # numpy, scipy, matplotlib
python -m pip install -r requirements-figures.txt  # + pandas, sequentialized_barnard_tests
```

Python 3.11+. Pinned versions are the ones the reproduction checks were run
with; the figure pipeline is version-sensitive around matplotlib styling, so
prefer the pins when regenerating committed-looking output.

The figure pipeline sets `MPLBACKEND=Agg`, `PYTHONHASHSEED=0` and
`PYTHONDONTWRITEBYTECODE=1` itself — do not rely on an interactive backend.

## Layout

```
data/                  193 setting JSON files (read-only evidence)
shared_inputs.json     source documents shared across settings
task_metadata.json     frozen LIBERO / LIBERO+ task name and variant tables
source_inventory.json  per-document provenance
validation.json        pairing-coverage report, regenerated by scripts/validate.py
reproduce.py           top-level driver: materializes packed inputs, runs figure code
scripts/
  analyze.py           one-comparison CLI (McNemar + paired equivalence)
  paired.py            pairing engine
  equivalence.py       paired Newcombe score-interval equivalence (binary)
  plot.py              overview success-vs-steps figures
  validate.py          re-validates the export
  figures/             retained paper figure/statistics code (see below)
figures/               ALL generated output — untracked
```

`scripts/figures/` mirrors the paper pipeline and is organized per benchmark:

- `<benchmark>/tri_statistics_STEP/` — inference-step comparisons, violin figures
  and Markdown reports.
- `<benchmark>/tri_statistics_TOST/` — equivalence testing and its figures/reports.
- `real_world/tri_statistics_McNemar/` — real-robot paired McNemar.
- `TOST_analysis/gen_tost_verdict_tables.py` — compact LaTeX verdict tables.
- `analyse_flow_ablation_crossbench.py` — cross-benchmark scatter plots.
- `*/make_*_latex_table_glyph.py` — the glyph LaTeX result tables.

Each `tri_statistics_*` package splits the same way: `config.py` (constants,
model order, styling), `io_*.py` (loading), `pairs.py` (pair construction),
`stats.py` / `equivalence.py` (the test), `plotting.py`, `report.py`, `run.py`
(CLI entry point). Put a change in the layer it belongs to.

## Two views of the same export

Setting files hold both:

1. **Normalized rows** (`episodes`, `aggregates`, `task_counts`) — read by
   `analyze.py`, `paired.py`, `plot.py`, `validate.py`.
2. **Packed source payloads** (`source_documents`) — the original JSON/JSONL with
   SHA-256 provenance, read by the retained paper code in `scripts/figures/`.

`reproduce.py` unpacks view 2 into a temporary directory, runs the paper code
there, copies `.png/.pdf/.svg/.tex/.md/.csv` back into `figures/`, and deletes
the temp tree.

**Never edit one view alone.** They must stay consistent; a change needs a
regenerated export from the original log tree, not a hand-patched file. The
export-side scripts are not part of this repository.
Absolute paths inside provenance payloads are historical strings and are never
used to locate anything.

## Pairing rules

Join within the same model / checkpoint / evaluation cohort by
**(suite, task, episode_id)** — never by row position, never by aggregate
success rate. Different models use different task identifiers; this export does
**not** establish cross-model pairing, and no analysis should invent it.

| Data | Trial identity |
| --- | --- |
| LIBERO | Task plus recorded episode index |
| LIBERO+ | Exact task/perturbation variant plus episode index |
| RoboTwin | Task plus simulation seed |
| Real world | Task plus session timestamp and pair ID |
| CALVIN | Initial state and full task chain, or recorded sequence index |

- `pairing_basis` distinguishes explicit identities from `assumed_order`.
  X-VLA's older CALVIN and LIBERO evaluations are positional; pairing them
  requires the evaluation-order assumption and `analyze.py --allow-order`.
- `analyze.py` defaults to complete pairing. `--allow-partial` permits an
  intersection and reports exclusions; it is also required when sources conflict
  or parsed logs disagree with aggregate counts. Inspect the file's
  `normalization` diagnostics before reaching for it.
- Missing success labels are null, never failures. Duplicate keys are rejected.
- Real-world session IDs keep restarted pair numbers from colliding; both sides'
  policy seeds and initial positions are checked.
- Never manufacture per-episode outcomes from multi-trial success/failure counts.
  Single-trial LIBERO+ counts identify one binary outcome; multi-trial
  count-only variants stay marginal counts.

## Statistical conventions

- Differences are always **high minus low** (more inference steps minus fewer).
- Binary success: exact two-sided McNemar plus the paired Newcombe score-interval
  equivalence procedure in `scripts/equivalence.py`. Default margin **0.03
  (3 percentage points)**, alpha **0.05**.
- CALVIN chains additionally use paired-t TOST with a **0.15-subtask** margin.
- A claim of "no difference" is made with **TOST against the pre-registered
  margin**, never by failing to reject a null. Failure to reject is not evidence
  of equivalence — do not report it as such.
- The paired step-comparison Wilcoxon tests in `tri_statistics_STEP` are
  **within-model** comparisons. Report raw per-comparison p-values; do not apply
  a Holm or other multiplicity correction across models — the models are not one
  family here. The retained paper pipelines keep their own correction families
  where they define one; don't add or remove one without being asked.
- `analyze.py` is a single-comparison CLI and deliberately applies no
  multiple-comparison correction.
- Pooled episode estimates and task-level estimates answer different questions.
  Task labels are retained so both are available; say which one a number is.
- Canonical model order for tables, legends and figures:
  **dit, smolvla, xvla, flower, pi05, lap, mibot**. Real-world data labelled
  `openpi` is the same model as `pi05`. Keep this order everywhere.

Reference implementations: statsmodels
[`mcnemar`](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)
and [`ttost_paired`](https://www.statsmodels.org/stable/generated/statsmodels.stats.weightstats.ttost_paired.html).

## Evaluation cohorts

Every setting carries `setting.evaluation`. The cohorts are not interchangeable:

| Cohort | Settings | Read by the figure pipeline |
| --- | --- | --- |
| `primary` | 55 | yes — 44 by `reproduce.py`, the rest by `scripts/plot.py` |
| `checkpoint` | 104 | no — checkpoint sweeps for pi05, dit, xvla, flower |
| `horizon_sweep` | 34 | no — action-horizon sweeps across five models |

Only `primary` feeds the committed figures. That is not a reason to delete the
`checkpoint` and `horizon_sweep` cohorts: they are the sweeps behind the
appendix claims and have no `primary` equivalent.

Two cohorts were removed from this export and must not come back:

- The superseded `legacy` cohort (2026-09-10).
- The per-run RoboTwin Pi0.5 `run-<timestamp>_<config>` settings and the
  `robomimic_tool_hang` settings (2026-09-10). RoboTwin now covers X-VLA only;
  there is no RoboTwin Pi0.5 data and no robomimic benchmark in this export.

The export-side classifier still recognizes all of these — as `evaluation:
"legacy"`, `evaluation: "run-<timestamp>"` and `benchmark:
"robomimic_tool_hang"` — so a full re-export from the original tree will
reintroduce them; drop them again if you regenerate.

## Known data caveats

Read `VALIDATION.md` before drawing conclusions from edge cases. Across all 193
settings there are no conflicting log observations, and exactly three defects:

- **`libero__pi05__n10__checkpoint__ckpt-29k_pretrainedVLM`** — aggregates report
  40 tasks x 50 trials = 2,000; the console logs yield **37** episode outcomes.
  30 tasks have zero logged episodes, 10 are partial (2-7 of 50).
- **`libero__pi05__n1__checkpoint__ckpt-29k_pretrainedVLM`** — 1,000 of 2,000
  trials logged. `libero_10` and `libero_object` are complete; **`libero_goal`
  and `libero_spatial` have zero logged episodes** for all 20 of their tasks.
- **`libero__pi05__n1__horizon_sweep__h1`** — one success/failure line in
  `eval_libero_spatial_n1_shard3.log` (offset 21560) has no intact task/episode
  context. It sits in `unidentified_log_outcomes`, unassigned. That setting's
  2,000 episodes are otherwise complete and reconcile with its aggregates.

For the two 29k_pretrainedVLM settings the task-level `task_counts` are sound and
the episode-level record is not. Never pair them into a "complete run"; the
per-task mismatch detail is in `normalization.log_aggregate_mismatches`.

The Polaris benchmark and the GR00T model were removed from this export
(2026-09-09); references to them should not reappear.

## Verifying a change

```bash
python scripts/validate.py            # export integrity + pairing coverage
python reproduce.py all               # full figure/table regeneration
```

`reproduce.py all` is the real integration test — it exercises every retained
paper script. It takes a few minutes and writes ~33 MB into `figures/`.
Run it after touching anything in `scripts/figures/`.

If `validate.py` changes `validation.json`, that diff is meaningful: explain it,
don't just commit it.

## Committing

- `figures/` and all `.png`, `.pdf`, `.tex`, `.svg` are gitignored. Generated
  assets are never committed — the commands above regenerate them.
- The Markdown reports written under `figures/` are generated too; they are
  covered by the `/figures/` ignore rule, not by an extension rule.
- Do not commit `.mplconfig/`, `__pycache__/`, or virtualenvs.
- Keep `data/` byte-stable. A change there needs a regenerated export and a
  matching `validation.json`, not a manual edit.
